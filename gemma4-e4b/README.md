# Gemma 4 E4B-it on Trainium2

Google's [gemma-4-E4B-it](https://huggingface.co/google/gemma-4-E4B-it) (~7.9B params) on Trainium2.

**BREAKTHROUGH:** E4B is a **multimodal model** — it requires `mm_token_type_ids` from the processor. Without this input, the model degenerates (repeats or produces garbage). With proper processor inputs, it produces perfect text:

```
Q: What is the capital of France?  → A: The capital of France is **Paris**.
Q: What is 2+2?                    → A: 2 + 2 = **4**
Q: Explain gravity in one sentence → A: Gravity is the fundamental force of attraction between any two objects with mass.
```

## The Root Cause (why ALL prior attempts produced garbage)

E4B is `Gemma4ForConditionalGeneration` — a **multimodal** model. The text decoder backbone requires `mm_token_type_ids` (generated by the multimodal processor) to distinguish text tokens from multimodal placeholders. Without this tensor:
- The model produces degenerate repetition on CPU
- On Neuron, it produces multilingual garbage

This is NOT a Neuron bug, NOT a precision issue, NOT a PLE issue. It's a **missing input tensor**.

## Reproduction (CPU reference — works today)

```python
from transformers import AutoProcessor, AutoModelForCausalLM
import torch

proc = AutoProcessor.from_pretrained("google/gemma-4-E4B-it")
model = AutoModelForCausalLM.from_pretrained(
    "google/gemma-4-E4B-it",
    torch_dtype=torch.bfloat16,
    device_map="cpu",
    attn_implementation="eager",
)

messages = [{"role": "user", "content": [{"type": "text", "text": "What is 2+2?"}]}]
text = proc.apply_chat_template(messages, add_generation_prompt=True, tokenize=False)
inputs = proc(text=text, return_tensors="pt")  # includes mm_token_type_ids!

with torch.no_grad():
    out = model.generate(**inputs, max_new_tokens=50, do_sample=False)
print(proc.decode(out[0][inputs.input_ids.shape[1]:], skip_special_tokens=True))
# → "2 + 2 = **4**"
```
